## 三、给开发者自己的备忘（**不要发出去**）

### 官方接口约定（以此实现，域名待邮件确认）

| 用途 | 端点 | 关键点 |
|---|---|---|
| 授权 | `GET {authorizeUrl}` | 参数 `client_id`、`response_type=code`、`redirect_uri`、`scope`、`state` |
| 换令牌 | `POST {tokenUrl}` | **`application/x-www-form-urlencoded`**，body：`client_id`、`client_secret`、`grant_type=authorization_code`、`code`、`redirect_uri`；支持 `grant_type=refresh_token` |
| 用户信息 | `GET {userInfoUrl}?access_token=xxx` | token 走 **query 参数**，不是 `Authorization` 头 |

返回示例：

```json
{ "id": 1, "username": "BG5UWQ", "avar_url": "", "email": "", "is_email_confirmed": 1 }
```

### 实现时必须注意的 5 点

1. **没有独立 `callsign` 字段** → `callsignField` 用 `username`（社区用户名即呼号，需 `toUpperCase()`）。
2. **`oauth_sub` 用 `id`**，不要用 `username`（呼号可能变更，`id` 稳定）。
3. **PKCE 默认关闭**：官方参数表里没有 `code_challenge` / `code_verifier`，大概率不支持。避免参数被拒，仅用一次性 `state` 防 CSRF。
4. **回调地址按本地配置**（用户决策）：`http://localhost:9993/api/auth/oauth/callback`，走配置项并支持 `OAUTH_REDIRECT_URI` 环境变量覆盖。
   注意官方要求严格匹配，所以该值必须与对方登记值一致；在没有官方审核的情况下，本地想先验证流程可临时接自建 Keycloak 等标准 OIDC 提供方。
5. **同名账号不许自动合并**：`username` 就是呼号，而本站 `users.callsign` 是唯一键，任何 HamCQ 用户都能命中同名本站账号 →
   首次 OAuth 登录若发现同名账号已存在，**必须要求输入该账号的本站密码完成绑定**，否则拒绝登录。

### 落地配置（`config.json` 的 `oauth` 段）

```json
"oauth": {
  "enabled": false,
  "provider": "hamcq",
  "label": "使用 HamCQ 登录",
  "clientId": "",
  "clientSecret": "",
  "authorizeUrl": "https://【审核邮件下发】/oauth/authorize",
  "tokenUrl": "https://【审核邮件下发】/oauth/token",
  "userInfoUrl": "https://【审核邮件下发】/api/user",
  "scope": "user.read",
  "callsignField": "username",
  "userSubField": "id",
  "redirectUri": "http://localhost:9993/api/auth/oauth/callback",
  "usePkce": false,
  "tokenRequestFormat": "form"
}
```

> `enabled: false` 时登录页不显示「使用 HamCQ 登录」按钮，因此**代码可以先合入，凭据到位再开**。
